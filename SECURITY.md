# Security Policy

## Supported Versions

Only the latest deployment of Nego-Lah in production (`https://negolah.my` and `https://api.negolah.my`) is supported with security updates.

| Target / Component | Supported |
| :--- | :--- |
| Production Frontend (`https://negolah.my`) | :white_check_mark: |
| Production API (`https://api.negolah.my`) | :white_check_mark: |
| Local / Development Builds | :x: |

## Reporting a Vulnerability

We take the security of Nego-Lah and our users very seriously. If you have found a security vulnerability, please disclose it responsibly:

- **Primary Contact:** [terryong30@gmail.com](mailto:terryong30@gmail.com)
- **Secondary Contact:** [support@negolah.my](mailto:support@negolah.my)
- **Security.txt:** [https://negolah.my/.well-known/security.txt](https://negolah.my/.well-known/security.txt)

Please include the following information in your report:
1. Type of vulnerability (e.g., XSS, CSRF, authentication bypass, SQL injection, information disclosure).
2. Step-by-step instructions or proof-of-concept (PoC) to reproduce the issue.
3. Potential impact and affected endpoints or components.
4. Any suggested mitigations or patches.

### Vulnerability Handling & Response SLA

- **Acknowledgment:** Within 24-48 hours of receipt.
- **Triage & Severity Assessment:** Within 72 hours.
- **Remediation & Patch Deployment:** Critical/High issues will be addressed within 7 days.
- **Public Disclosure:** We ask that you do not disclose any vulnerability publicly or to third parties until a fix has been deployed and verified.
